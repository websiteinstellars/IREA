How these numbers are made
  • Coverage. A rule-based matcher compares each uploaded bank CDH action with the reference CDH's actions (by default this site's own Pega CDH) on wording, using banking synonyms (for example FD, CD and time deposit count as the same thing). Covered = an equivalent exists; Partial = it exists but is missing channels, a suitability check, part of the audience, or only loosely matches by name; Missing = none. The matcher is automatic, so treat each match as a lead to confirm, not a verdict. Channels, suitability and audience are only judged when both datasets provide them.
  • Value. Each reference action is priced from an editable assumptions table: customers it can reach, response-rate range, and annual value per converted customer. Each range is sampled 2,000 times; P10 is the cautious case, P50 the most likely, P90 the optimistic case. The defaults are placeholders, not the bank's real figures. Values are annual.
  • Totals add up action-level values, so the P10 and P90 totals are wider than a combined simulation would give.
  • Partial actions count part of their value as missing; change the share with the control at the top.
  • Treatments, policies and contact rules. When the bank file is a Pega action catalog export, every matched pair is also compared on its treatments (a live treatment per channel, and whether it carries message text, subject, link and image), its eligibility, suitability and applicability conditions (matched by customer field, then by operator and value) and its contact policies (trigger and suppression period). Pega When rules are not in the catalog export and are not compared.
  • Needs data: missing actions whose rules read a signal the bank said it does not have. They are listed, not priced. Only applies when a list of available data signals is supplied.
